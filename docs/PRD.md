# 수원시 도서관 토털 웹사이트 개선 PRD

**핵심 개선 타스크:** 도서 검색 및 대출 가능 여부 확인하기

---

## 1. 문서 개요 (Document Overview)

### 1.1 프로젝트 목적
수원시 도서관 웹사이트의 도서 검색·상세 화면에서 이용자가 **대출 가능 여부를 정확하고 쉽게 판단**할 수 있도록 개선한다. 색상 의존 표기, 반납예정일 미표시, 행정 용어 사용, 소장 정보 불일치 등으로 인해 이용자가 상태를 오인하거나 도서관 방문 후 헛걸음하는 문제를 해소한다.

### 1.2 목표
- 색상에 의존하지 않는 상태 표기(텍스트 라벨 + 테두리)를 도입하여 KWCAG 2.2 기준을 충족한다.
- 대출 중 도서의 반납예정일을 명시하여 이용자의 예약·방문 판단을 지원한다.
- 행정 용어를 일상 용어로 바꾸고 도움말을 제공한다.
- 대출 상태와 소장 정보를 일치시켜 정보 신뢰성을 확보한다.
- 검색 필터, 예약·관심도서·책배달 연계 버튼, 마이페이지 진입점을 마련하여 핵심 과업의 연속성을 보장한다.

### 1.3 준거 기준
- KWCAG 2.2 (5.4.1 색에 무관한 콘텐츠 인식, 5.4.3 명도 대비, 5.3.1 표의 구성, 4.1.3 상태 메시지)
- 10 Usability Heuristics (#1, #2, #3, #4, #7, #8, #10)
- 디지털 정부서비스 UI/UX 가이드라인

### 1.4 개선 우선순위 (자료 내 테마 구조화 결과)

| 테마 | 내용 | 우선순위 |
|---|---|---|
| 테마 1 | 마이페이지 진입점 및 퀵 메뉴 신설 | P1 |
| **테마 2** | **대출 상태 인지성 및 포용적 정보 전달** | **P0 (가장 시급)** |
| 테마 3 | 검색 필터 및 예약·책배달 CTA 연결 | P1 |
| 테마 4 | 대출 상태-소장 정보 데이터 상충 정정 | P0 |
| 테마 5 | UI 컴포넌트 일관성 및 예외 상태 검증 | P2 |

> **테마 2 최우선 선정 사유:** KWCAG 2.2 법적 준수 의무 항목이며, 반납예정일 미표시와 행정 용어 오인이 연체 피해 및 오프라인 헛걸음을 직접 유발함.

## 2. 타겟 페르소나 (Target Persona)

**전체 타겟:** 도서 검색, 대출·반납 상태 확인, 예약을 이용하는 수원시민 전체

### 페르소나 1. 박영수 님 (68세, 적록색약 및 노안이 있는 고령 이용자)

| 구분 | 내용 |
|---|---|
| 상황 | 도서 검색 후 결과 목록에서 대출 가능 여부를 확인하고, 도서관 방문 여부를 결정함 |
| 기대치 | 대출 가능 여부를 한눈에 구별하고, 안심하고 도서관을 방문하는 것 |
| 불편 사항 | ① 작은 글씨와 낮은 명도 대비로 눈의 피로가 큼<br>② 초록/빨강 원형 아이콘만으로는 대출 상태를 구별하지 못해 오인함<br>③ "비치중" 등 행정 용어의 의미를 이해하지 못함<br>④ 대출 중인 책을 대출 가능으로 오인하여 헛걸음함 |

### 페르소나 2. 김아름 님 (26세, 스크린 리더를 사용하는 시각장애 대학원생)

| 구분 | 내용 |
|---|---|
| 상황 | Tab 키와 스크린 리더로 도서 카드를 탐색하고, 대출 상태 확인 후 예약을 진행함 |
| 기대치 | 스크린 리더 음성만으로 상태를 정확히 파악하고, 타인의 도움 없이 예약까지 완료하는 것 |
| 불편 사항 | ① 대체 텍스트가 없어 배지가 "이미지/버튼"으로만 낭독됨<br>② 반납예정일이 없어 반납 시점을 알 수 없음<br>③ "예약자수 0/2"가 "영 슬래시 이"로 읽혀 의미가 혼동됨<br>④ 상태 확신이 없어 타인에게 확인을 요청하거나 예약을 포기함 |

> 전체 타겟(수원시민)의 연령·이용 빈도 등 세부 특성은 **추가 확인 필요**

## 3. 핵심 사용자 여정 (Core User Journey)

### 3.1 개선된 타스크 흐름 (요약)

```
[메인] 도서 검색
   → [검색 결과 목록] 필터 적용(대출가능 도서만 보기, 도서관 선택)
   → 상태 배지(텍스트+테두리) 및 반납예정일 확인
   → [도서 상세] 소장도서관 표에서 도서관별 청구기호·대출상태·반납일 확인
   → 서가 위치 배치도 확인
   → 대출 가능: 도서관 방문 / 대출 중: [예약하기]
   → [예약 완료 모달] 대기 순번·예상 수령일 확인
```

### 3.2 박영수 님 (고령·적록색약) 개선 여정

| 단계 | 행동 | 개선 후 경험 |
|---|---|---|
| 1. 목록 진입 | 검색 결과 목록 탐색 | 16px 이상 서체, 명도 대비 4.5:1 이상 적용으로 가독성 확보 |
| 2. 상태 인지 | 대출 가능 여부 확인 | [대출가능], [대출중] 텍스트 배지와 테두리로 한눈에 구별 |
| 3. 용어 파악 | "비치중" 문구 확인 | "대출 가능 (서가에 비치됨)" 표현 및 툴팁으로 즉시 파악 |
| 4. 방문 결정 | 도서관 방문 판단 | 정확한 대출 가능 정보를 확인하고 안심하고 방문 |

### 3.3 김아름 님 (스크린 리더) 개선 여정

| 단계 | 행동 | 개선 후 경험 |
|---|---|---|
| 1. 음성 탐색 | Tab 키로 도서 카드 탐색 | 배지 대체 텍스트로 "대출 가능, 배지"가 정확히 전달됨 |
| 2. 반납일 확인 | 대출 중 도서 상태 확인 | "대출중, 반납예정일 2026년 10월 15일" 음성 출력 |
| 3. 수치 파악 | 예약 현황 영역 접근 | "예약 가능 인원 2명 중 현재 0명 예약됨" 보조 설명 제공 |
| 4. 예약 완수 | 예약 버튼 실행 | 정확한 정보 파악 후 주도적으로 예약 과업 완료 |

## 4. 기능 요구사항 (Functional Requirements)

> ⚠️ **세부 디자인 스펙(색상 코드, 크기 등)은 다음 단계에서 확정 예정.** 본 장은 "어떤 기능을 어떻게 개선하는가" 수준까지 기술한다.

### 4.1 메인 화면

| ID | 기능 | 개선 내용 |
|---|---|---|
| FR-01 | 마이페이지 진입점 | 로그인 후 상단 퀵 영역에 [내 대출현황/마이페이지] 버튼을 명확히 배치한다. |
| FR-02 | 퀵 메뉴 단축 항목 | 퀵 아이콘 바 최우선 위치에 [대출·반납·연장 조회] 단축 메뉴를 배치한다. |

### 4.2 검색 결과 목록

| ID | 기능 | 개선 내용 |
|---|---|---|
| FR-03 | 필터 | [☑ 대출가능 도서만 보기] 토글 및 도서관 선택 스코프를 신설한다. |
| FR-04 | 대출 상태 배지 | 초록/빨강 색상 단독 표기를 폐지하고, [대출가능]/[대출중] 텍스트 라벨 + 테두리로 다중 식별한다. 범례를 제공한다. |
| FR-05 | 반납예정일 표시 | 대출중 배지 옆에 `반납예정일: YYYY-MM-DD`를 명시한다. |
| FR-06 | 용어 개선 | "비치중" → "대출 가능 (서가 비치)", "예약자수 0/2" → "예약 가능 인원 2명 중 0명 대기"로 변경하고, 도움말(툴팁)을 제공한다. |
| FR-07 | 도서 카드 CTA | 도서 카드 하단에 [예약하기], [관심도서], [책배달] 버튼을 노출한다. |
| FR-08 | 스크린 리더 대응 | 상태 배지에 대체 텍스트를 제공하여 "대출 가능, 배지", "대출중, 반납예정일 OOOO년 O월 O일" 형태로 낭독되도록 한다. |

### 4.3 도서 상세 화면

| ID | 기능 | 개선 내용 |
|---|---|---|
| FR-09 | 상태 정보 일치 | 상단 대출 상태와 하단 소장 목록을 DB 연동 정정으로 100% 일치시킨다. |
| FR-10 | 소장도서관 표 | 소장도서관, 청구기호, 대출상태, 반납일을 포함한 구조화된 표를 출력한다. 표 마크업(`<caption>`, `<th>`, `<td>`)을 적용한다. |
| FR-11 | 서가 위치 안내 | 청구기호 옆 [서가 위치 배치도 보기] 버튼을 제공하고, 팝업으로 연결한다. |
| FR-12 | 용어 설명 | 소장도서관 표 하단에 인라인 용어 설명 패널을 상시 노출한다. |
| FR-13 | 책 소개·ISBN | 외부 DB 연동으로 정보를 채우고, 데이터가 없는 경우 해당 컨테이너를 노출하지 않는다. |

### 4.4 대출 예약 과업

| ID | 기능 | 개선 내용 |
|---|---|---|
| FR-14 | 예약 완료 피드백 | 예약 완료 모달에 내 대기 순번과 반납예정일 연동 예상 수령일을 표시한다. |
| FR-15 | 상태 메시지 접근성 | 완료 시 `aria-live="assertive"` 속성으로 스크린 리더 사용자와 시각 사용자 모두에게 확정 피드백을 제공한다. |

### 4.5 예외 처리 및 에러 로직

| 구분 | 요구사항 | 근거 |
|---|---|---|
| 책 소개·ISBN 데이터 없음 | 빈 컨테이너를 노출하지 않음 (FR-13) | 자료 명시 |
| 상태 불일치 | 상단 상태와 소장 목록이 일치하도록 DB 연동 정정 (FR-09) | 자료 명시 |
| 소장도서관 정보 없음 | 공란 방치 금지 | 자료 명시 (대체 문구는 **추가 확인 필요**) |
| 예약 실패, 예약 한도 초과, 로그인 만료, 네트워크 오류, 검색 결과 0건 등 | 처리 로직 및 메시지 | **추가 확인 필요** (현황 분석에 "다양한 시스템 예외 상태(State) 교차 검증 미완성"으로 기재되어 있어 후속 정의 필요) |
| 반납예정일 미확정·연체 중 도서 | 표시 방식 | **추가 확인 필요** |

## 5. UI/UX 및 정책 요구사항 (UI/UX & Policy Requirements)

### 5.1 공공언어 가이드라인

| As-Is | To-Be | 근거 원칙 |
|---|---|---|
| 비치중 | 대출 가능 (서가 비치) | Heuristic #2 현실 세계와 일치 |
| 예약자수 0/2 | 예약 가능 인원 2명 중 0명 대기 | Heuristic #2, #10 |

- 내부 행정 용어를 사용하지 않고, 이용자에게 익숙한 표현과 도움말(툴팁·인라인 설명)을 함께 제공한다.
- 그 밖의 용어 전수 점검 및 표준 용어집은 **추가 확인 필요**

### 5.2 시각적 우선순위

1. 대출 상태 배지(텍스트 + 테두리)를 도서 카드 내 최우선으로 인지되도록 배치한다.
2. 대출중인 경우 반납예정일을 배지 바로 옆에 배치한다.
3. 예약·관심도서·책배달 CTA는 카드 하단에 직접 노출한다.
4. 색상은 보조 수단으로만 사용하며, 색상 단독으로 정보를 전달하지 않는다. (KWCAG 5.4.1)

### 5.3 레이아웃 및 접근성 규칙

| 항목 | 요구사항 |
|---|---|
| 대응 환경 | 모바일 360px 이상 |
| 그리드 | 4컬럼 그리드 |
| 터치 타겟 | 44px 적용 |
| 서체 크기 | 16px 이상 |
| 명도 대비 | 4.5:1 이상 |
| 표 구조 | `<caption>`, `<th>`, `<td>` 적용 |
| 상태 메시지 | `aria-live="assertive"` 적용 |

> 구체적인 색상 코드, 배지 형태·크기, 아이콘 세부 규격은 **다음 단계에서 확정 예정**

### 5.4 정책 요구사항
- KWCAG 2.2 및 디지털 정부서비스 UI/UX 가이드라인을 준수한다.
- 별도 운영 정책(예: 예약 한도, 연장 가능 횟수, 예상 수령일 산정 기준)은 자료에 없으므로 **추가 확인 필요**

## 6. 성공 지표 (Success Metrics)

### 6.1 사전 설정 목표 (가설 기반)

| 지표 | 목표 수치 |
|---|---|
| 대출 가능 여부 판단 시 오인 오류 횟수 | 0회 |
| 과업 성공률 | 100% |

**대상:** 고령자와 시각장애인을 포함한 모든 이용자

### 6.2 실제 테스트 측정 결과 (Peer UT)

**테스트 과업:** 도서 검색 후 대출 가능 여부 및 반납예정일 확인하기
**평가 대상:** 동료 평가자 10명 (개선 후 와이어프레임 기준)

| 지표 | 결과 |
|---|---|
| 한 번에 찾은 사람 수 | 10명 (100%) |
| ① 매우 쉬움 (오류 없이 한 번에 성공) | 8명 |
| ② 쉬움 (단순 탐색 후 성공) | 2명 |
| ③ 어려움 (도움을 받아 성공) | 0명 |
| ④ 매우 어려움 (과업 실패 및 오인) | 0명 |

### 6.3 목표 대비 결과

| 지표 | 목표 | 실측 | 판정 |
|---|---|---|---|
| 오인 오류 | 0회 | 0명 (④ 응답 0명) | 달성 |
| 과업 성공률 | 100% | 100% | 달성 |

**가설 판단:** 계속 (Keep / 가설 검증 완료)

### 6.4 개선 전(As-Is) 테스트 피드백 요약

- 초록/빨강 원만으로는 고령자·색약 사용자가 대출 가능 여부를 구별할 수 없었음
- 반납예정일이 없어 예약 여부를 판단할 수 없었음
- "비치중"이 생소하여 도서관에 직접 가야만 빌릴 수 있는 것인지 혼동함

### 6.5 한계 및 추가 확인 필요 사항

| 항목 | 내용 |
|---|---|
| 평가자 구성 | 동료 평가자(Peer UT) 10명이며, 실제 고령자·색약자·스크린 리더 사용자 참여 여부는 자료에 명시되지 않음 → **추가 확인 필요** |
| 개선 전 수치 | As-Is 화면의 정량 결과(성공률·오류 횟수)는 자료에 없음 → **추가 확인 필요** |
| 테스트 대상 | 와이어프레임 기준 테스트이므로, 실제 구현 후 재검증 계획은 **추가 확인 필요** |
| 보조 지표 | 연체율, 헛걸음 감소율, 과업 소요 시간 등은 자료에 없음 → **추가 확인 필요** |

> 동료 평가 기반 결과이므로, 대표성 확보를 위해 실제 페르소나 해당 이용자 대상의 추가 검증을 권고한다.

## 7. 반응형

### 7.1 브레이크포인트

- 모바일: ~767px
- 태블릿: 768px ~ 1439px
- 데스크탑: 1440px ~

### 7.2 기본 원칙

- 모바일 우선(Mobile First)으로 설계·구현한다.
- 기본 스타일은 모바일 기준으로 작성하고, 미디어쿼리는 min-width 방식으로 태블릿(768px), 데스크탑(1440px)에서 점진적으로 확장한다.
- 1440px 이상의 큰 화면에서는 콘텐츠 최대 폭을 제한(max-width, rem 단위)하고 가운데 정렬한다. 배경은 화면 전체를 채운다.

### 7.3 단위 규칙

- 레이아웃 구성 시 상대 단위(%, rem)를 사용하고, 고정 px 너비는 지양한다.
- em 단위는 사용하지 않는다. 단, letter-spacing은 Figma의 % 자간을 옮기기 위해 em을 허용한다.
- 아래 항목은 px 사용을 허용한다.
  - border / outline 두께 (예: 1px)
  - box-shadow, border-radius
  - 미디어쿼리 브레이크포인트 값 (768px, 1440px)

### 7.4 디자인 전달

- 사이즈별 상세 반응형 디자인(모바일/태블릿/데스크탑)은 구현 단계에서 이 섹션에 추가한다. 그 전에는 임의로 구조를 가정하지 않는다.
- 모바일은 Figma 완성화면(`3-4. 완성화면`의 Mobile 섹션)을 따른다.
- 태블릿·데스크탑은 완성화면이 없어, 담당자 요청에 따라 데스크탑 와이어프레임(`3-1. 와이어프레임`의 Desktop 섹션)을 참고해 아래처럼 정했다. 완성화면이 나오면 그 내용으로 바꾼다.

| 화면 | 태블릿 (768px ~ 1439px) | 데스크탑 (1440px ~) |
|---|---|---|
| 공통 | 좌우 여백 32px, 콘텐츠 최대 폭 1280px 가운데 정렬 | 좌우 여백 64px, 콘텐츠 최대 폭 1280px 가운데 정렬 |
| 메인 | 퀵메뉴 4열, 추천 도서 3열, 도서관 안내와 강좌 2열, 검색창 가운데 | 환영 문구와 퀵메뉴(2 x 2) 좌우 배치, 나머지는 태블릿과 같음 |
| 검색 결과 | 도서 2열, 조건은 별도 화면 | 왼쪽에 조건 패널 고정, 오른쪽에 도서 2열 |
| 검색 조건 | 가운데 한 열 (최대 폭 640px) | 가운데 한 열 (최대 폭 768px) |
| 도서 예약 | 가운데 한 열 (최대 폭 640px) | 왼쪽 요약, 오른쪽 내용의 2열 |
