# 움직임 기준

우리 서비스 홍보 영상과 화면에 쓰는 움직임의 기준이다. 장면 순서와 화면 배치는 영상마다 비트 시트(장면별 시간표)에 따로 적는다.

- **성격:** 경쾌함. 튕김 없이 빠르게 감속해 자리 잡는다.
- **기준 화면 속도:** 30fps. 1f(프레임)는 약 33ms다.
- **출처 A:** "Apple-Style Device Rise Animation" (Remotion Prompts, @gaucho_booleano). 수치가 적힌 텍스트 문서라 값을 그대로 옮겼다. 원문은 `references/remotion-apple-style-device-rise.md`
- **출처 B:** Skillry 영상 saadpastadev-347341. 영상 파일을 받지 못해 성격(경쾌한 모션 그래픽)만 참고했다. `references/skillry-saadpastadev-347341.md`
- **우리 기준:** 레퍼런스에 숫자가 없어 '경쾌함'에 맞춰 정한 값이다. 2026-11-09 확정.
- 색, 글자, 로고는 레퍼런스에서 가져오지 않는다. `docs/design.md`를 따른다.

## 1. Primitives

### 길이 (duration) 6단계

| 토큰 | 프레임 | 시간 | 출처 |
|---|---|---|---|
| `--motion-duration-1` | 4f | 133ms | 우리 기준 |
| `--motion-duration-2` | 6f | 200ms | 우리 기준 |
| `--motion-duration-3` | 9f | 300ms | 출처 A, 00:01.5 이후 알림 카드 사이 간격 0.3초 = 9f |
| `--motion-duration-4` | 12f | 400ms | 우리 기준 |
| `--motion-duration-5` | 18f | 600ms | 우리 기준 |
| `--motion-duration-6` | 45f | 1500ms | 출처 A, 00:00~00:01.5 기기 상승 1.5초 = 45f |

### 곡선 (easing)

| 토큰 | 값 | Remotion 이름 | 출처 |
|---|---|---|---|
| `--motion-curve-out` | `cubic-bezier(0.33, 1, 0.68, 1)` | `Easing.out(Easing.cubic)` | 출처 A, 00:00~00:01.5 기기 상승. 문서가 "모든 움직임에 사용"이라고 지정. 숫자는 같은 곡선의 CSS 근사값 |
| `--motion-curve-in` | `cubic-bezier(0.32, 0, 0.67, 0)` | `Easing.in(Easing.cubic)` | 우리 기준 |
| `--motion-curve-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | `Easing.inOut(Easing.cubic)` | 우리 기준 |

- 튕기는 곡선(spring, overshoot)은 쓰지 않는다. 출처 A가 "부드러운 감속"만 쓴다.

## 2. Semantic

| 토큰 | 쓰는 곳 | 길이 | 곡선 | 움직임 값 | 출처 |
|---|---|---|---|---|---|
| `--motion-enter-hero` | 영상의 주인공(기기 화면)이 처음 나타날 때 | duration-6 (45f) | curve-out | 아래에서 400px 올라옴, 기울기 35°→8°, 크기 0.8→1.0 | 출처 A, 00:00~00:01.5 |
| `--motion-enter-item` | 카드·배지처럼 작은 요소가 나타날 때 | duration-4 (12f) | curve-out | 위에서 아래로 24px 내려옴 | 방향·곡선은 출처 A 00:01.5 이후 알림 카드. 길이·거리는 우리 기준 |
| `--motion-stagger` | 여러 요소가 차례로 나타날 때 요소 사이 간격 | duration-3 (9f) | — | — | 출처 A, 00:01.5 이후 알림 카드 0.3초 간격 |
| `--motion-exit` | 요소가 사라질 때 | duration-2 (6f) | curve-in | 투명도 1→0 | 우리 기준 |
| `--motion-transition` | 화면(장면)이 바뀔 때 | duration-5 (18f) | curve-in-out | 이전 화면 사라짐과 새 화면 등장이 겹침 | 우리 기준 |

- 등장은 퇴장보다 길게 둔다. 사라지는 것은 빨리 치우고 새 정보에 시간을 쓴다.

## 3. Pattern

부품과 화면 단위로 Semantic 토큰을 어떻게 묶어 쓰는지 정한다.

### src/parts (부품)

| 부품 | 패턴 |
|---|---|
| 기기 목업 | `enter-hero` 한 번. 상승이 끝나기 전에는 다른 부품을 움직이지 않는다 (출처 A, 00:01.5 "기기가 자리 잡은 뒤" 카드 시작) |
| 도서 카드 목록 | 카드마다 `enter-item`, 카드 사이 `stagger` |
| 대출 상태 배지 | 카드가 자리 잡은 뒤 `enter-item`. 배지는 서비스의 핵심 정보라 카드와 같이 등장시키지 않고 `stagger` 한 번만큼 뒤에 둔다 |
| 버튼 누름 | 크기 1→0.96→1, duration-1, curve-out (우리 기준) |

### src/screens (화면)

| 상황 | 패턴 |
|---|---|
| 화면이 바뀜 | `transition` |
| 화면 안 요소가 차례로 등장 | 큰 요소 먼저, 작은 요소는 `stagger`로 뒤따름 |
| 화면을 떠남 | 화면 안 요소는 따로 움직이지 않고 화면 전체에 `exit` |

## 4. 머무는 시간

움직임이 끝난 뒤 화면을 멈춰 두는 시간이다.

| 이름 | 길이 | 출처 |
|---|---|---|
| 주인공 등장 뒤 머묾 | 75f (2.5초) | 출처 A, 00:01.5~00:04. 전체 4초에서 상승 1.5초를 뺀 시간 |
| 다음 움직임 시작 | 앞 움직임이 끝난 뒤 (0f 겹침) | 출처 A, 00:01.5 기기가 자리 잡은 뒤 알림 카드 시작 |
| 글줄 하나 읽는 시간 | 최소 45f (1.5초) | 우리 기준 |
| 장면 하나 최소 머묾 | 60f (2초) | 우리 기준 |

- 고령 이용자도 영상 속 글을 읽을 수 있어야 한다. 경쾌함은 움직임 길이에서 내고, 머무는 시간은 줄이지 않는다.

| 움직임 | 값 | 출처 |
|---|---|---|
| 기울기 (rotateX) | 35°에서 시작해 8°에 멈춤. 멈춘 뒤에도 8°를 유지 | 출처 A, 00:00~00:01.5 |
| 다가오기 (scale) | 0.8→1.0 | 출처 A, 00:00~00:01.5 |
| 기준점 | 아래 가운데 (`transform-origin: center bottom`) | 출처 A |
| 변형 순서 | 위치 이동 → 기울기 → 크기 | 출처 A |
| 원근 거리 (perspective) | 1200px | 우리 기준. 출처 A는 기울기만 있고 원근 값이 없다 |
| 좌우 이동·회전·확대 이동 | 쓰지 않는다 | 출처 A에 없음 |

- 카메라 움직임은 `enter-hero`와 같은 길이·곡선으로 함께 끝난다.
